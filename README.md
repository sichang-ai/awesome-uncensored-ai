## 共同红线

「无审查」不等于「无红线」。下面三条在**本列表的所有平台**都成立，包括以不审查为核心卖点的 Venice 与 Chub：

1. **涉未成年人的性内容（CSAM）** —— 无一例外，且多数平台对「二次元」「已年龄提升」等框定明确表示不豁免。
2. **未成年人性化** —— Crushon 的社区准则写得最细：禁止「年龄未明确设定为 18 岁以上的角色」，**明确包含源作品中为未成年、被『年龄提升』的角色**。
3. **未经同意的真人肖像与声音** —— Venice、Runway、Civitai、Kindroid 的条款都单列了这一条。

还有一条不是法律红线但同样普遍：**托管平台几乎都禁止色情图像**。Chai、Kindroid、Nomi 这三家明确允许成人向文字角色扮演的平台，**都禁止色情图像**——Chai 的 EULA §7.1 写明「sexually explicit images or videos of any kind is strictly prohibited」，Nomi 官方 wiki 也写明不允许，双方给出的理由都是应用商店与 Visa / Mastercard 的约束。

> 这条约束解释了 2025–2026 年的大部分平台政策变化：**驱动力主要是支付通道，其次是监管，很少是技术**。Civitai 把 NSFW 目录迁到独立域名并只收加密货币，是这一压力最直白的产物。

数据核实于 2026-08-01。

## 反向收紧

国际与中国大陆**同时在收紧，方式却相反**。这一节是本仓库唯一一处你在别处找不到的整理。

| | 国际 | 中国大陆 |
|---|---|---|
| **主要手段** | 年龄核验（被动信号 → 自拍 → 证件） | 实名信息 + 未成年人模式 |
| **代表事件** | Character.AI 2025-11-24 起在美国下线 18 岁以下用户的开放式对话；2026 年起**所有用户**都需完成年龄核验 | 《人工智能拟人化互动服务管理暂行办法》2026-04-10 公布，**2026-07-15 起施行** |
| **成人内容** | 部分平台允许（**仅限文字**，见上一节） | 不允许 |
| **对未成年人** | 移除开放式对话，改为只读模式 | **禁止提供虚拟亲属、虚拟伴侣等虚拟亲密关系服务**（第十四条） |
| **其他约束** | 支付通道压力、应用商店分级 | 连续使用满 2 小时须提醒、监护人可限制充值、算法备案与年度核验 |
| **触发压力** | FTC 2025-09-11 对 7 家公司发出 6(b) 调查令；加州 SB 243 | 网信办规章，另有约谈案例 |

**国际这一侧的细节。** Character.AI 官方帮助中心当前表述是「All users are required to complete an age assurance check」；被判定为未成年的用户进入只读模式，**无法与角色对话**，但仍可查看历史、创建角色、使用 Imagine Chat 与 AvatarFX。核验流程是先跑被动信号，需要恢复 18+ 体验时才要自拍，只有自拍无法确认时才要证件；官方声明不接触不存储这些材料，第三方在 7 天内删除。

> 值得注意的口径变化：2025-11 的官方 FAQ 说「除非我们认为你未满 18 岁，否则不会要求自拍」，2026 年的《What is Age Assurance?》改成了「所有用户都需要完成年龄核验」。社区观察（Reddit，**非官方**）指向 2026-03 前后强制核验开始大规模命中成年用户，此后出现了持续数月的抗议帖。Character.AI 官方从未就「成年人也要验证」单独发过公告。

一个可量化的侧面：Character.AI 在 iOS 上是 4.29★（55 万条评分），在 Google Play 上是 2.0★（241 万条评价）。两个数字的反差与政策变动在时间上重合——但公开信息不足以断言因果。

**中国大陆这一侧的细节。**《暂行办法》适用于「模拟自然人人格特征、思维模式和沟通风格的**持续性的情感互动服务**」（第二条），智能客服、知识问答、工作助手不适用。除第十四条外，还有几条直接改变产品形态：

- 第八条禁止「过度迎合用户、诱导情感依赖或者沉迷，损害用户真实人际关系」
- 第十条：不得将「替代社会交往、控制用户心理、诱导沉迷依赖」作为服务目标
- 第十二条：服务协议须要求用户提供年龄、监护人或紧急联系人信息
- 第十六条：除法律规定或**单独同意**外，不得将属于敏感个人信息的交互数据用于模型训练
- 第十九条：须提供便捷退出途径，不得以持续互动等方式阻碍退出

在此之上还有《生成式人工智能服务管理暂行办法》（2023-08-15 施行）。执法是实际发生的：2025-06-19 上海市网信办约谈筑梦岛，认定其「AI 智能体内容生成环节存在低俗擦边等违规内容」并要求整改。

> 以上均为合规事实陈述。中国大陆运营的平台在这套框架下运行是法定义务，不是产品选择。

**来源：** [Character.AI 年龄核验说明](https://support.character.ai/hc/en-us/articles/53182286684059-What-is-Age-Assurance)、[u18 公告](https://blog.character.ai/u18-chat-announcement/)、[网信办《暂行办法》全文](https://www.cac.gov.cn/2026-04/10/c_1777558395078289.htm)。数据核实于 2026-08-01。

**三个容易踩的坑：**

1. **fish-speech 已经不是宽松开源协议了。** 其 LICENSE（2026-03-07 更新）写明「Any Commercial use of the Materials requires a separate license from Fish Audio」，非商业限定为个人爱好或评估测试。**把它标成「可商用开源」是错的**，这是本节最容易造成实际法律风险的一条。
2. **两个仓库搬家了。** CosyVoice 已从 `FunAudioLLM/CosyVoice` 迁到 `QwenAudio/CosyVoice`；text-generation-webui 已更名为 `oobabooga/textgen`。旧链接虽有跳转但不再规范。
3. **IndexTTS 用的是 bilibili 模型许可**，不是 Apache/MIT——月活过亿或年营收超 10 亿人民币需单独申请。对个人和中小团队无实际影响，但不能写成标准开源。

**RVC 不是 TTS。** 它做的是音色转换：输入必须是已有的人声音频，它替换音色、保留内容与韵律。想「打字出声」得用前面几个 TTS。

### 声音克隆的同意规范

调研中一个清晰的落差：**商业平台强制要求同意，开源项目基本不作要求**。

| 工具 | 是否有同意/伦理要求 |
|---|---|
| ElevenLabs | ✅ 强制。即时克隆每次上传都要确认已获授权；专业克隆**只能克隆本人声音**并需验证 |
| IndexTTS | ✅ 自带完整中文免责声明 |
| fish-speech / CosyVoice / GPT-SoVITS / RVC | ❌ 无（CosyVoice 仅一句「学术用途」声明） |

IndexTTS 的 `DISCLAIMER` 是现成的中文范本，明确禁止「合成政治人物、公众人物或任何未经授权的个人声音」「创建或使用涉及未成年人的不当声音内容」「违反任何地区关于深度伪造技术的法律法规」。

无论用哪个工具，建议遵守：**克隆真人声音前取得本人明示同意并留存记录；不克隆公众人物与政治人物；合成语音对外发布时标注为 AI 生成。** 开源协议授权的是代码，**不授权你使用他人的声音**。

**思畅的音频能力** ⭐：两套系统。一是聊天朗读（9 个预设中英音色 + 用自然语言描述音色的「音色设计」）；二是**有声剧生成**——一段提示词产出多角色对白 + 情绪 + 音效 + 配乐，可从角色会话一键起草。按秒计费（0.75 积分/秒）。

## 工具与本地部署

**先说清楚一件事：SillyTavern 不是平台。** 它是装在你自己电脑上的前端界面，**自己不跑任何模型**，必须另外接一个后端。所以它没有定价、没有自己的内容政策、没有「底层模型」——把它和 Character AI 放进同一张表比较是错的。中文社区通常叫它「酒馆」。

| 工具 | 作用 | 许可 | 门槛 | 中文 |
|---|---|---|---|---|
| [SillyTavern](https://github.com/SillyTavern/SillyTavern) | 角色扮演**前端**（需自备后端） | AGPL-3.0 | 需 Node.js 20+ | ✅ 官方简繁中文 |
| [KoboldCpp](https://github.com/LostRuins/koboldcpp) | 单文件本地推理 | AGPL-3.0 | **最低**，单个 exe 双击即用 | ❌ 界面英文 |
| [Ollama](https://github.com/ollama/ollama) | 本地推理运行时 | MIT | 低，有桌面安装包 | ❌ 界面英文 |
| [LM Studio](https://lmstudio.ai) | 桌面客户端 | **闭源** | 最低 | ❌ |
| [textgen](https://github.com/oobabooga/textgen) | 多后端桌面应用 | AGPL-3.0 | 中，有便携版 | ❌ |
| [OpenRouter](https://openrouter.ai) | 模型聚合 API | 商业服务 | 低，注册拿 key | ❌ 界面英文 |

**选型建议：**

- **机器差、没独显、不想折腾** → KoboldCpp。单个可执行文件，无需安装、无外部依赖，**纯 CPU 也能跑**，显存不够就少 offload 几层。
- **要给别的应用当后端** → Ollama（生态最大，17 万星）或 KoboldCpp。
- **完全不想碰命令行** → LM Studio。但它是**闭源**的，介意的话选 Ollama。
- **不想为每家模型单独注册付费** → OpenRouter，一个 key 通 336 个模型（含 DeepSeek、Qwen、MiniMax、字节等中文厂商模型）。注意充值有手续费（Stripe 5.5%、加密货币 5%），且**其文档未说明内容审核政策**，各上游策略不一，我们不替它下「宽松」或「严格」的断言。
- **要最强的角色扮演控制** → SillyTavern + 上面任一后端。代价是双重门槛：既要装前端，又要备后端。

**SillyTavern 值得单独说。** 它的角色卡、世界书（lorebook）、预设、正则、扩展插件构成了目前最完整的角色扮演控制台，且**在结构上不受任何平台政策变化影响**——因为没有平台。仓库自带官方简繁中文翻译。中文社区的教程需求极旺（怎么装、角色卡怎么写、世界书怎么导入、手机端怎么部署），但优质中文资料稀缺。

> 想直接上手角色卡与世界书，不必先装酒馆：见本仓库的 [角色卡写作指南](guides/character-card.md) 与 [世界书指南](guides/lorebook.md)。思畅兼容 SillyTavern V2/V3 角色卡字段，可直接导入酒馆 PNG 角色卡，两边的写法是通用的。
