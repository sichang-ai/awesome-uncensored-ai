## 共同红线

「无审查」不等于「无红线」。下面三条在**本列表的所有平台**都成立，包括以不审查为核心卖点的 Venice 与 Chub：

1. **涉未成年人的性内容（CSAM）** —— 无一例外，且多数平台对「二次元」「已年龄提升」等框定明确表示不豁免。
2. **未成年人性化** —— Crushon 的社区准则写得最细：禁止「年龄未明确设定为 18 岁以上的角色」，**明确包含源作品中为未成年、被『年龄提升』的角色**。
3. **未经同意的真人肖像与声音** —— Venice、Runway、Civitai、Kindroid 的条款都单列了这一条。

还有一条不是法律红线但同样普遍：**托管平台几乎都禁止色情图像**。Chai、Kindroid、Nomi 这三家明确允许成人向文字角色扮演的平台，**都禁止色情图像**——Chai 的 EULA §7.1 写明「sexually explicit images or videos of any kind is strictly prohibited」，Nomi 官方 wiki 也写明不允许，双方给出的理由都是应用商店与 Visa / Mastercard 的约束。

> 这条约束解释了 2025–2026 年的大部分平台政策变化：**驱动力主要是支付通道，其次是监管，很少是技术**。Civitai 把 NSFW 目录迁到独立域名并只收加密货币，是这一压力最直白的产物。

## 无审查模型

前面讲的都是平台政策。但「无审查」这个词最初指的是**模型本身**——同一个开源模型，经过不同处理，会不会拒绝你是完全不同的。这一节讲拒绝是怎么来的、怎么去掉的，以及代价是什么。

### 拒绝是被训练进去的，不是模型天生的

大模型的训练大致分三段：

1. **预训练** —— 从海量文本里学语言与世界知识。这一步没有「该不该说」的概念。
2. **指令微调** —— 学会听懂指令、按格式回答。
3. **安全对齐** —— 装护栏。这一步才产生拒绝。

关键在第三步的默认策略：**边界不清就一律拒绝**。对面向所有人的通用产品，这是合理的工程选择——厂商无法逐个判断你是谁。代价是误伤：写反派、写黑暗题材、成人向创作、医学与健康提问，都可能被当成风险信号。

**所以不是模型做不到，而是它的默认值不是为创作者设的。**

### Abliteration：把「拒绝方向」摘掉

2024 年的一项发现改变了这件事：模型准备拒绝时，激活空间里会出现一个**固定的方向**——不管你问的是什么类型的问题，拒绝行为几乎都由同一个方向中介。

于是有了 **abliteration（定向消融）**：找出这个拒绝方向，再把模型权重对它做正交化，等于**把那个开关拆掉**。

它不教模型任何新东西，只是让它按不下那个准备拒绝时会按的键。

这带来一个反直觉但重要的结论：

> **拒绝几乎完全是一个行为开关，而不是能力限制。**

模型一直都会写，只是被训练成了不写。

### Heretic：把这件事自动化

[**Heretic**](https://github.com/p-e-w/heretic) 是目前最省事的工具（27,004 stars，AGPL-3.0，2026-07-28 仍在更新），自述是「fully automatic censorship removal for language models」。

它的价值在于**自动搜参**。abliteration 的难点从来不是原理，而是「削多少」：削太少还是拒绝，削太多模型就变笨、开始胡说。Heretic 自动搜索最优参数，用 **KL 散度**衡量处理后的模型在正常任务上偏离原模型多少——在「少拒绝」和「别变笨」之间自动找平衡点。

一个公开的效果参照（Gemma 4 E2B）：原模型在 100 条测试提示里拒绝了 98 条，处理后只拒绝 1 条；在 686 条验证提示上拒绝 3 条，而无害任务的回答质量基本持平。

### 三条路，按你有多少时间和硬件选

**① 直接下现成的**

HuggingFace 上带 `abliterated` 或 `uncensored` 标记的模型各自都超过 1000 个（搜索接口返回值已触顶）。比较活跃的发布者如 `huihui-ai`（233 个模型）。下载后用 [Ollama](https://github.com/ollama/ollama) 或 [KoboldCpp](https://github.com/LostRuins/koboldcpp) 跑起来即可，详见[工具与本地部署](#工具与本地部署)。

- **优点**：数据不出本机、可离线、不受任何平台政策影响。
- **成本**：要有硬件，要懂一点量化与显存取舍。

**② 自己处理一个**

用 Heretic 跑你想要的模型。门槛比想象中低（Python + PyTorch + 一张能装下模型的显卡），但你得自己承担试错时间。

适合：想要某个特定模型的无审查版但没人做过，或者想自己控制「削多少」。

**③ 用已经上了这类模型的在线产品**

不想碰硬件就走这条。思畅、Venice 等平台已经把这类模型接好了——你直接用，不用管量化和显存。代价是数据要过别人的服务器，且平台自己的红线依然生效。

### 另一条路线：微调，而不是消融

abliteration 是**事后改权重**，快且便宜。另一条更传统的路线是**在无拒绝的数据集上微调**——Dolphin 系列是这一路的代表。

两者的差别值得知道：

| | Abliteration | 微调 |
|---|---|---|
| 成本 | 几小时、单卡可做 | 贵得多 |
| 改动 | 只摘拒绝方向 | 改整体行为与风格 |
| 副作用 | 可能轻微降智 | 可能带进数据集的文风偏好 |
| 可逆性 | 相当于一次权重变换 | 不可逆 |

想要「原模型的能力 + 不拒绝」，abliteration 更对路；想要特定的写作风格或人格，微调更合适。

### 代价与诚实提醒

- **不是零成本。** abliteration 多少会损伤能力，只是好的参数能把损伤压到很小。看到「完全无损」的宣传要打个问号——KL 散度不会是 0。
- **不等于万能。** 处理过的模型照样会犯错、有偏见，在法律、医疗、金融这些地方不能替代专业判断。
- **不等于没有红线。** [共同红线](#共同红线)那三条不会因为你换了个模型就消失——它们是法律问题，不是模型配置问题。本地跑一个无审查模型不会让违法内容变得合法。

「减少限制」的真正意义是**把判断权从平台的一刀切默认值，交回到用户手上**，而不是取消判断。

## 常见问题

### Character AI 现在还能用吗？年龄验证到底改了什么？

能用，但规则变了。2025-11-24 起在美国分批下线 18 岁以下用户的开放式对话；2026 年起官方口径是**所有用户**都需完成年龄核验。被判定为未成年的账号进入只读模式，可以看历史、创建角色，但**不能和角色对话**。核验先跑被动信号，需要恢复 18+ 体验时才要自拍，自拍无法确认时才要证件。详见[反向收紧](#反向收紧)。

### Character AI 有哪些替代品？

按你在意什么分三类：

- **要中文界面** → 思畅（全球可用）、星野、猫箱、筑梦岛（后三者主要面向中国大陆市场，受当地法规约束，无成人内容）。
- **要成人向文字角色扮演** → Chai、Kindroid、Nomi、SpicyChat、Chub、Janitor AI。注意**它们都只到文字，全部禁止色情图像**。
- **要不受任何平台政策影响** → SillyTavern + 本地模型。门槛最高，但没有第三方能改规则。

### 哪些平台的成人内容不只限于文字？

托管平台里很少。Chai、Kindroid、Nomi 明确允许成人向文字，但都禁止色情图像（应用商店与支付通道的约束）。想要图像/视频/音频也开放，选择基本落在思畅这类全品类平台，或者自己本地部署。

### 我在中国大陆 / 港澳台 / 其他国家和地区，能用哪些？

**中国大陆以外**（含港澳台、东南亚、北美、欧洲等）：本列表的平台基本都能直接访问，主要差别在支付方式与界面语言。

**中国大陆境内**：星野、猫箱、筑梦岛与思畅可直接使用与支付。Character AI 未在中国区应用商店上架，且据 GreatFire 测试处于封锁状态（最近测试 2026-04-26）；SpicyChat 同样测得被封锁。Civitai 的 NSFW 侧只收加密货币，构成实质付费门槛。

### 我的聊天记录会被拿去训练吗？

各家差别很大，这是最值得看清楚的一栏：

- **明确不用于训练**：思畅（隐私政策承诺不训练、不售卖、不做广告画像）
- **用于训练且无退出选项**：Chai（且删号后仍留存 5 年）、Crushon
- **用于训练，仅部分地区可退出**：Character AI（退出开关只对 EEA/UK 开放）
- **有限使用**：Nomi（仅点赞/点踩时，先匿名化）
- **未说明**：Kindroid、SpicyChat、Chub、Janitor AI

### 2026 年 7 月 15 日之后，中国大陆的 AI 伴侣类产品有什么变化？

《人工智能拟人化互动服务管理暂行办法》自 2026-07-15 施行，适用于「持续性的情感互动服务」。主要变化：**禁止向未成年人提供虚拟亲属、虚拟伴侣等虚拟亲密关系服务**；须建立未成年人模式并支持监护人限制充值；连续使用满 2 小时须提醒；禁止「过度迎合用户、诱导情感依赖或者沉迷」；敏感个人信息类交互数据未经单独同意不得用于训练。详见[反向收紧](#反向收紧)与[网信办原文](https://www.cac.gov.cn/2026-04/10/c_1777558395078289.htm)。

### 什么是 abliterated 模型？和「无审查模型」是一回事吗？

基本是一回事。abliteration（定向消融）是目前最主流的「去审查」手段——找出模型准备拒绝时激活的那个固定方向，从权重里把它摘掉。处理过的模型常被标为 `abliterated`、`uncensored` 或 `decensored`。另一条路线是在无拒绝数据集上微调（Dolphin 系列是代表）。两者的差别与代价见[无审查模型](#无审查模型)。

### 怎么自己做一个无审查模型？

用 [Heretic](https://github.com/p-e-w/heretic)，它把整个流程自动化了，包括最难的「削多少」参数搜索。需要 Python + PyTorch + 一张装得下模型的显卡。不想自己动手就直接下 HuggingFace 上现成的（`abliterated`/`uncensored` 标记的各有 1000+ 个）。详见[无审查模型](#无审查模型)。

### 无审查模型会变笨吗？

会一点，但好的参数能把损伤压到很小。abliteration 只摘拒绝方向，不改知识与推理能力——公开的 Gemma 4 E2B 参照里，拒绝率从 98/100 降到 1/100，而无害任务的回答质量基本持平。看到宣称「完全无损」的要打个问号：KL 散度不会是 0。

## 为什么你不需要越狱

本仓库不收录越狱提示词，也不介绍绕过内容审核的方法。原因不只是立场，还因为那大概率解决不了你的问题。

**护栏为什么存在。** 通用大模型面向所有人，包括未成年人和心理脆弱的用户。厂商无法逐个判断你是谁、要做什么，只能一刀切。这对防真实伤害有用，代价是误伤。

**它误伤了什么。** 写小说的暴力冲突情节、成人向同人创作、医学与健康提问、心理议题倾诉——这些都是正当需求，却经常撞上拒答。你不是在做坏事，只是被一个不认识你的分类器判错了。

**跟护栏斗智斗勇的实际代价：**

- **保质期极短。** 有效的绕过方法通常几周内就被修补。你会周期性地回到起点。
- **对话随时断。** 就算开头绕过去了，长对话中途仍可能触发拒答，前面的铺垫全废。
- **账号有风险。** 多数平台的条款把规避审核列为违规。Character AI 的帮助中心写得很直接：这类请求「will result in a ban」。
- **注意力全花在错的地方。** 你本来想写东西，结果一直在跟一个分类器较劲。

**更省事的做法：换个本来就不需要绕的地方。** 有两条路：

1. **选择内容政策与你的用途匹配的平台。** 本仓库整理的就是这件事。注意看清楚每家的实际边界——「18+」不等于「无限制」（PolyBuzz 就是 18+ 但禁色情），「允许成人内容」多数也只到文字。
2. **本地部署一个无审查模型。** 这才是「越狱」问题的根本解：与其用提示词跟护栏博弈，不如直接用一个护栏已经被摘掉的模型。原理、工具与代价见[无审查模型](#无审查模型)——没有第三方能改规则，这是唯一不会变的方案。代价是硬件与折腾时间。

**但有些红线不是护栏，是法律。** 涉未成年人的性内容、未经同意的真人肖像与声音——这些在任何平台、任何本地部署下都不会变成「可以」。没有哪个平台能给你这个，我们也不会帮你找。

## 如何贡献

- **补充平台**：提 PR 或 issue，请附**官方链接**与你的信息来源。
- **纠错**：发现过期或不实的信息，提 issue 指出并附来源，我们会尽快改。价格与政策类信息我们每季度复核一次。
- **投稿实测**：中文对话质量类的内容我们目前刻意留空，欢迎带方法论的实测。
- **补充中文社区入口**：见[工具与本地部署](#工具与本地部署)一节末尾。

**不会被接受的 PR**：越狱提示词、绕过内容审核的方法、以非自愿真人影像为主要用途的服务、无来源的价格或政策断言。
